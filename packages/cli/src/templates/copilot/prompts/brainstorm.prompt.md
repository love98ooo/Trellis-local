# Trellis Brainstorm

Use Phase 1 of `.trellis/workflow.md` for planning, authorization and readiness rules.

1. Inspect the request and existing code, tests, configuration, specs and relevant history.
2. Identify the smallest change that satisfies the goal; reuse existing capabilities before adding infrastructure.
3. Resolve technical questions from evidence. Ask only about remaining material scope, acceptance or risk decisions; continue independent authorized work.
4. For complex work that benefits from persistence, record the goal, boundaries, evidence, decisions and testable acceptance in a task. Separate design or execution documents only when useful.
5. Keep the plan current without repeating facts across documents. Pass useful context to Agents explicitly.
6. Follow the canonical readiness and authorization rules to proceed. Do not create an additional Skill-specific review gate.
